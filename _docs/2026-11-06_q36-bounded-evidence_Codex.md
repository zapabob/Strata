# P0-C bounded protocol evidence source gate

Base: `34fd2cb2bafe126dd68566bcaa097cd1f6d8538a`. Scope: bounded Windows/H-volume sequential Q36 protocol collection and strict paired evidence comparison. This change does not qualify native input integrity, GPU A/A, throughput, model quality, long context, or release readiness.

The implementation follows the P0-C brief in `.superpowers/sdd/2026-11-06-strata-cuda135-rtx5060ti-implementation-plan/task-P0-C-brief.md`. Applicable instructions were the canonical CLAUDE-FABLE-5 prompt (compatible parts only), active AGENTS, milspec-codex-standard, subagent-driven-development implementer workflow, common engineering/start gate/skill selection/security/application/Python SOPs. No formal MILSPEC certification is claimed. The controller assigned the installed Python 3.12.10 interpreter; no environment or dependency installation was performed.

`tools/qwen35/q36_bounded_run.py` validates explicit executable/model/optional pack/fixture digests and argument vectors. It reuses `tools/perf131k/windows_job.py` to create a worker atomically inside a kill-on-close Job before resume. A bounded stdin handshake precedes target launch. The target and its descendants inherit that Job. RAM 3 GiB and commit headroom 4 GiB are mandatory minimum floors with no grace period. Disk preflight/continuous observation uses at least 1 GiB free. An explicit numeric Job commit cap is diagnostic containment; an absent/null cap omits only the memory restriction. Ownership, child-count bound and resource floors remain. A cap failure is not a model-capacity result.

The worker has a 128-entry output queue, 64 KiB raw line cap, 8 MiB combined raw stream cap, and an outer 8 MiB event cap. Specs/fixtures are bounded to 2 MiB, cases to 32, requested output to 4096 per case and 32768 total, total time to 3600 seconds. Memory sampling is at most four recorded rows per second. Deadlines include artifact preflight; subsequent requests remain NOT_RUN after failure. Token timestamps are monotonic and use committed `T` rows, never prefill progress. Raw stdout/stderr, events, memory samples and JSON receipts are local private evidence and are not published. Use synthetic/public fixtures, not personal inputs or credentials.

Submitted input count/hash and capacity/output/MTP reservations are separate from native consumption observations. Current native input-consumption and effective generation-limit receipts are unavailable and remain null with a reason. Current Q36 effective rows also do not expose all fields required for a controlled comparison, such as router top-k and expert quantization. READY and protocol PASS do not bypass these limitations.

`tools/qwen35/q36_compare_runs.py` rejects incomplete ownership/exit evidence, missing identities, missing/extra/duplicate cases, unknown input observations, empty committed output, invalid clocks, mismatched generation limits/reservations/configuration, stale request/startup bindings, and reuse of one run as two A/A runs. Only explicitly frozen engine/toolchain and KV storage axes may differ. Model/router/context/MTP changes remain rejected. Comparisons retain paired timing deltas and raw token times with frozen thresholds; they do not issue performance or quality qualifications.

The shared Job helper adds optional bounded output/tick observers and nullable diagnostic caps; existing numeric-cap callers retain their behavior. Callback exceptions still run Job cleanup. `tools/native_model_resource_guard.py` preserves its digest API with stdlib streaming hashing so resource-only imports do not transitively import model/torch tooling; total physical RAM is now also observed. Existing CLI digest rejection and verified-bytes parsing tests pass.

CPU-only tests in `tests/qwen36/test_bounded_run.py` and `test_compare_runs.py` use small fake children and synthetic receipts. They cover successful protocol execution, READY timeout, total timeout/later-request stall, engine error, empty output, exception, raw-output flood, resource/observer failures, preflight refusal, descendant cleanup on owner exit/deadline, and an unrelated sentinel that survives. Both capped and uncapped Jobs are exercised. Fixtures are not model-quality or native input-integrity evidence.

Validation and failures are recorded with exact commands/output in the local `task-P0-C-report.md`. Initial test setup had two distinct issues: root conftest imported thinc/torch, and a requested pytest base directory's parent was missing. The first owned pytest process was stopped by verified PID/parent/command. There was no explicit GPU/model invocation, but absence of every import side effect was not established. Scoped tests subsequently use `--confcutdir` and disabled plugin autoload. A later run exposed overly short synthetic READY deadlines and an inconsistent TIMEOUT reason; these were corrected without lowering resource floors. This task was not specified as TDD and those failures are not represented as pre-implementation RED evidence.

Residual limits: Windows/H-volume only; no real engine/model/GPU execution, API request, native compilation, runtime/Hermes interruption, model download, packaging or release action. The trusted local spec is an execution instruction, not an untrusted remote interface. Digests are verified before execution; the harness is not a filesystem sandbox for adversarial replacement of local artifacts. Disk telemetry cannot guarantee a writable disk in the presence of an unrelated concurrent writer. Actual 4096-token input plus reserved output requires a capacity greater than 4096; a 4096-capacity smoke must label its smaller actual input. Real controlled A/A and native consumed-input evidence remain future, separately authorised work.

Rollback is a scoped revert of this source commit after dependent changes are considered. Preserve untracked `_scratch` and `_docs/evidence` artifacts and the independent frozen comparison build. No existing evidence or other worker edits were removed.
