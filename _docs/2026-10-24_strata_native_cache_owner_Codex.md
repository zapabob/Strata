NativeCacheRequested is a versioned in-memory typed contract. K/V are independently selected pinned Turbo KV dialects, distinct from weight formats. F32 compressed and diagnostic F32 are separate representations. Alpha must explicitly be a valid simplex; all-zero input is rejected. F16/BF16 coefficients, unknown enums, nonresident modes, position transport and nonzero QJL beta are rejected before device work. Geometry and execution arithmetic are validated before attachment. No manifest parser or model receipt producer is implemented here.

NativeCacheBinding explicitly requires independently verified ordered raw model SHA-256s, the loader's exact sorted/unique normal-layer directory, the selected logical layer index and the resolved position digest. This API does not establish the truth of those caller inputs. Sidecar expectations are built from the caller, never read from the sidecar. All unit identities are synthetic. The base profile includes the strict coupled three-representation Spin matrices, pinned F convention, codec, alpha, precision, representation, mode and position, excluding adapter content and execution limits. The layer digest includes every ordered raw digest plus logical index and actual geometry. Adapter content is bound only after independent sidecar validation, avoiding a circular profile hash. The reviewed cache plan includes that layer digest and validated adapter content in its complete cache identity.

The immutable host plan owns bounded metadata and validated sidecar/identity parameter storage. It owns no CUDA allocation or FP32 history. Each NativeCacheOwner keeps a shared const plan and borrows one caller-allocated 256-aligned GPU region and one live explicit nondefault stream on the selected device. The exact region accounts for the reviewed cache arena, four per-head query-v3 parameter arrays, the sticky query status word and alignment. Three K planes and one shared V remain the reviewed layout; there is no duplicate legacy pool. No global mutable session cache is added.

Quiescent attachment/reinitialisation explicitly uploads immutable parameters, initializes/audits the reviewed cache and synchronizes the supplied stream. Every hot operation is asynchronous and has no allocation, synchronization, device switch or default-stream work. Query calls reuse spin8_query_v3_cuda_apply_batched_f32 on already Q-normalized input, without another RMS. No adapter and zero Wout/bout are exact v3 identity paths. The host-declared query token count must describe accessible initialized input; the adapter does not interpret cache command.query_rows. Bounded cache append/attend do read persistent counts.

The caller must keep plan, owner, stream, region, persistent commands and external GPU buffers alive through completion and all graph replays. SessionState should own the owner container and layers may borrow its pointers in the next integration phase. Quiesce/destroy graphs before owners or borrowed resources. Destruction does not synchronize. Completion observation requires runtime success, cache valid=1/status=0 and query status=0 before any output is consumed. Any observed failure permanently stops the owner until explicit quiescent reinitialisation; a host runtime failure sticks even if no GPU flag was written. This says nothing about other RNN/indexer/session state: the future orchestrator must invalidate those together.

The additive C functions accept the existing v1 append/attention structures plus a positive per-call token capacity no larger than the plan maximum. Legacy entry points share the implementation with plan maxima. Host spans/overflow/alias checks and launch bounds use the per-call capacity; GPU counts above it fail before tensor reads or publication. All C structs, versions, cache identities, snapshot layout and codec helper implementations are unchanged.
