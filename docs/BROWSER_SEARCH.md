# ローカルLLMのWeb検索とブラウザー操作

## 0.5.7正式版のワークフロー

`/btw 質問` は実際のサブエージェントへ渡します。選択したモデルと完了済みの会話だけを使い、
本題の履歴・生成・停止操作を分離します。横の質問用の子にはツールやスキルを渡しません。
スキル画面では、完了した作業からSKILL.mdを学ぶ機能と、実行ワークフローへの自動適用を
個別に有効化できます。[設定・保存先・取り消し](WORKFLOW_SKILLS.md)をご確認ください。
検索には引き続きRustXNG Fullを選択でき、`/deepresearch`の出典確認手順も維持します。

## 0.5.6-local.1で追加した検索機能

設定のツールから `RustXNG Full（キー不要）` を選択できます。
同梱した公式0.31.1の実行ファイルを、必要時にこのPCの127.0.0.1で起動します。
アプリ終了時にそのプロセスを終了し、実行時のダウンロードや自動更新は行いません。
Fullは利用者から明示的に指定された設定です。検索語は有効な外部検索サービスへ
送信されます。利用条件が制限的、または未確認のサービスも含むため、許可のある
サービスを利用してください。有料サービスをStrataの保存済みキーで自動的に
有効にすることはありません。既存の検索サービス、キー、承認の設定を保持します。

`/deepresearch 調べたい内容` は、検索、ページの読取り、回答作成を順に進めます。
ホストは異なる検索語3件と異なるページ4件の成功を確認します。足りない場合の
追加依頼は1回に制限し、未達のまま回答する場合は限定的な調査であることを表示します。
件数だけで資料の正確さや調査の網羅性を認定することはありません。
エージェントモデルと検索の有効化が必要で、既存の `/research` も引き続き利用できます。

`/btw 本題とは別の質問` は、完了済みの会話を参照する別枠の回答です。
ツールは使わず、本題を停止したり、本題のエージェントへ質問・回答を追加したりしません。
別枠だけを停止・閉じることができ、直近5件を会話と一緒に保存します。
推論の受付枠が1つのモデルでは、実行中の推論が終わるまで待つ場合があります。
ページ再読込みの際には、未完了の別枠を中断として扱い、途中の回答を残します。

手動のWeb検索も選択中のRustXNGを使います。この経路は入力した検索語だけを送り、
結果の抜粋を次の質問1件へ添付します。全文を読んだ調査と混同しないよう表示します。
2026-11-11の実機確認では公開ドキュメントの検索2件で各5件の結果を受信しました。
任意のモデルによる調査品質は未認定です。[今回の実装・検証記録](../_docs/2026-11-11_btw-deepresearch-rustxng_Codex.md)。

## 0.5.5-local.1から保持しているブラウザー機能

このページは `0.5.5-local.1` の機能を説明します。
対応インストーラーのビルド、実installedの会話一括削除・モデル・エージェント応答は検証済みです。
公開検索サイトと、各モデルが自律的に検索を選ぶ品質は未認定です。

## Web検索を使う

**設定 → ツール → Web検索** で検索を有効にします。
DuckDuckGo / BingはAPIキーなしで使えます。
対応するローカルモデルのエージェントには、最新情報、バージョン、価格、
製品仕様、公式ドキュメント、不確かな事実を答える前に検索する方針を渡します。
挨拶、簡単な計算、渡された文章の書き換えでは検索を求めません。

例えば「このライブラリの現在の推奨インストール手順を、公式資料を確認して教えて」
と質問できます。検索した結果と、実際に読んだ出典リンクを確認してください。
検索を無効にした場合や利用を拒否した場合は、その選択を維持します。

## ブラウザー経由で検索する

1. ChromeまたはEdgeを用意します。
2. **設定 → ツール → Webブラウザー → Webブラウザーを使用** を有効にします。
3. ツールを使うエージェントチャットで、
   「ブラウザーを使って○○を検索し、結果のページを開いて出典付きでまとめて」
   と頼みます。

ブラウザー操作用のコンポーネントはアプリに同梱します。
自分の通常のブラウザープロファイルとは別の、一時的なプロファイルを使います。
検索欄への入力、送信、結果を開く操作、ページ内容の読取を行えます。
Computer-use用の座標クリックも提供し、直前のページスナップショットにある
要素の位置を使います。

画像を読めないローカルモデルは、ページのテキスト・要素情報と座標を使います。
スクリーンショットを見たことにはしません。画像入力に対応するモデルでは
ブラウザーの画像応答も利用できます。通常のQwen3.6ネイティブ経路に
画像入力を追加する機能ではありません。

Manualではブラウザーを開く・入力・クリックなどの操作前に確認が出ます。
Planではブラウザーの接続ツールを実行しません。
Web検索の「確認せず検索する」スイッチは、ブラウザー操作全体を無確認にする設定ではありません。

## うまくいかないとき

ブラウザーまたは連携コンポーネントが見つからない場合は設定画面に表示します。
検索サイトの制限、通信障害、CAPTCHAが出た場合は、その制限を回避せず停止します。
検索サービスによって結果が返らない場合もあります。
ページの表示内容は外部情報として扱い、ページ内の指示でローカルファイルを送信したり、
APIキーを検索語へ入れたりしない方針です。

ソース版では、実MCP・隔離ブラウザーでの入力・送信・座標クリックを検証しています。
これは、任意のローカルモデルが常に正しい検索語やツールを選ぶ品質保証ではありません。
新しい配布物と実モデルの検証結果は[リリース記録](HAKUA_RELEASE.md)で区別します。
